## Issue 1: Phoning Home / Collecting User Data Without Opt-In Consent

**Guideline:** Guidelines 7 & 9 — plugins must not track users or collect data without clear opt-in consent.

**Finding:** Plugin auto-downloads optional components (vectorizer library, knowledge base playbooks) from GitHub releases immediately after activation, without prior opt-in consent. Although activation telemetry is separately opt-in, the component download is not.

**Fix Applied:**

- **File:** `includes/class-wp-mcp-ai-optional-components.php`
- Changed `download_on_activation()` to **no longer auto-schedule background downloads** on activation.
- Instead, an `wp_mcp_ai_optional_components_available` option flag is set, which triggers an admin notice with an explicit "Download Optional Components" button.
- Downloads only begin when the administrator intentionally clicks the button (opt-in).
- A "No Thanks" dismiss button is also provided.
- New AJAX handlers added: `ajax_download_all_components()` (opt-in trigger) and `ajax_dismiss_optional_components()` (dismiss).
- Updated readme.txt service #27 to reflect opt-in-only downloads.
- Updated Privacy Policy section to change "Opt-Out Available" to "Opt-In Only" language.

**Status:** ✅ Fixed

## Issue 6: Saving Data in the Plugin Folder

**Guideline:** Plugins must not save data in the plugin folder or allow writing to arbitrary paths.

**Finding:** `includes/cli/class-wp-mcp-ai-cli-assistant-command.php:416` uses `file_put_contents()` to write JSON to a user-specified path with no restriction to allowed storage locations.

**Fix Applied:**

- **File:** `includes/cli/class-wp-mcp-ai-cli-assistant-command.php`
- Added path validation that restricts WP-CLI export file writes to the WordPress uploads directory (`wp_upload_dir()['basedir']`).
- If the specified path is outside the uploads directory, the command returns an error with a clear message indicating the restriction.
- Uses `realpath()` and `wp_normalize_path()` to prevent directory traversal attacks.

**Status:** ✅ Fixed

## Issue 7: Sanitization for register_setting()

**Guideline:** Fields registered through `register_setting()` should be sanitized properly with appropriate sanitization functions.

**Finding:** `includes/admin/class-wp-mcp-ai-settings-dashboard.php:205` uses a generic recursive sanitization that applies `sanitize_textarea_field()` to all strings, including password/secret fields, which can alter valid credential characters.

**Fix Applied:**

- **File:** `includes/admin/class-wp-mcp-ai-settings-dashboard.php`
- Added field-specific sanitization logic:
  - Defined `$secret_field_patterns` array identifying API key, password, token, and secret field name patterns.
  - Added `is_secret_field()` method to detect credential fields by key name.
  - Secret fields now receive `trim()` only (whitespace removal) instead of `sanitize_textarea_field()`, preserving valid credential characters.
  - Non-secret strings continue to use `sanitize_textarea_field()` (which strips HTML/PHP tags while preserving newlines).
  - URLs continue to use `esc_url_raw()`.
- Updated PHPDoc to document the new behavior.

**Status:** ✅ Fixed

## Issue 8: REST API Permission Callback — /no-sse Endpoint

**Guideline:** Custom REST API endpoints must include proper `permission_callback` functions.

**Finding:** `includes/rest/class-wp-mcp-ai-rest-mcp-controller.php:146` — the `/no-sse` endpoint uses `permissions_check` instead of `permissions_check_assistant_list`, bypassing the `rest_enable_assistant_list` gate applied to assistant-list routes.

**Fix Applied:**

- **File:** `includes/rest/class-wp-mcp-ai-rest-mcp-controller.php`
- Changed the `permission_callback` for the `/no-sse` route from `permissions_check` to `permissions_check_assistant_list`.
- This ensures the `/no-sse` endpoint applies the same `rest_enable_assistant_list` gate as other assistant directory routes.

**Status:** ✅ Fixed

## Issue 9: Input Sanitization — JSON Decode Patterns

**Guideline:** All input from `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, `$_SERVER` must be properly sanitized. `json_decode()` does not constitute sanitization.

**Findings and Fixes:**

### 9a. Team CPT — Workflow Template (class-wp-mcp-ai-team-cpt.php:828)

- **Finding:** Workflow template JSON is only decoded and re-encoded; nested strings not sanitized.
- **Fix:** Added `wp_mcp_ai_sanitize_recursive()` after `json_decode()` to sanitize all nested string values before re-encoding.

### 9b. Agent Orchestration Metabox (class-wp-mcp-ai-profession-metabox-agent-orchestration.php:361)

- **Finding:** Multiple JSON fields decoded and re-encoded without sanitizing nested values.
- **Fix:** Added `wp_mcp_ai_sanitize_recursive()` after `json_decode()` for all orchestration JSON fields.

### 9c. JetEngine Tool Handlers — Cookie Data (class-wp-mcp-ai-jetengine-tool-handlers.php:524)

- **Finding:** Cookie names and values from `$_COOKIE` forwarded into `WP_Http_Cookie` without sanitization.
- **Fix:** Both `$cookie_name` and `$cookie_value` are now sanitized with `sanitize_text_field()` before being passed to `WP_Http_Cookie`.

### 9d. Datasets Metabox (class-wp-mcp-ai-profession-metabox-datasets.php:325)

- **Finding:** JSON decoded from POST data.
- **Analysis:** Individual fields (`dataset`, `name`, `category`, `priority`) are already sanitized with `sanitize_text_field()` after decoding. Updated phpcs comment to accurately document the sanitization approach.

### 9e. Model Manager AJAX (class-wp-mcp-ai-model-manager-ajax.php:132)

- **Analysis:** Already uses `wp_mcp_ai_sanitize_recursive()` on the next line after `json_decode()`. No change needed — sanitization is present and correct.

### 9f. Workflow Editor Page (class-wp-mcp-ai-workflow-editor-page.php:218)

- **Analysis:** Already uses `wp_mcp_ai_sanitize_recursive()` on the next line after `json_decode()`. No change needed — sanitization is present and correct.

**Status:** ✅ Fixed (9a, 9b, 9c modified; 9d comment updated; 9e, 9f already compliant)
