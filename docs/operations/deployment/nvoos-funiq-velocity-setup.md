## One-time activation

1. ✅ Private repos created (2026-10-29).
2. ✅ Monorepo secrets `NVOOS_FUNIQ_PWA_READ_TOKEN` /
   `NVOOS_FUNIQ_VELOCITY_REPO_TOKEN` set.
3. Run `sync-nvoos-funiq-velocity.yml` once via `workflow_dispatch`
   (builds the CMS in CI, migrates a throwaway Postgres, smoke-tests the
   Payload contract, force-pushes the mirror).
4. In Velocity: create a Node.js app, connect the mirror repo.

## Environment variables (app-level `.env` in Velocity)

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URI` | yes | PostgreSQL connection string (Payload postgres adapter) |
| `PAYLOAD_SECRET` | yes | Signs Payload auth cookies/JWTs — 64-char random |
| `HOSTNAME` | yes | `0.0.0.0` (bind) |
| `NODE_ENV` | recommended | `production` — skips devDependencies during `npm install` |
| `PORT` | no | **Injected by Velocity** — do not set manually (astro-leg precedent) |

## Database

The CMS requires PostgreSQL (`@payloadcms/db-postgres`). Any reachable
Postgres works (Velocity managed DB if available on the plan; otherwise a
managed Postgres provider). Schema management is explicit — Payload
production **never auto-pushes**:

- The mirror ships `src/migrations/` (generated by the sync workflow).
- Applying them to a fresh DB requires the full config, which lives in the
  **private source checkout**:
  `cd nvoos-funiq-pwa/payload-cms/funiq-cms && npx payload migrate`
  (with `DATABASE_URI`/`PAYLOAD_SECRET` exported).
- First boot at `/admin` runs Payload's standard "create first user" flow.

## Uploads (media)

Payload stores uploads on local disk under the app tree by default. A
git-connected Velocity redeploy that resets the working tree may drop
untracked upload files. **Open owner decision:** the vendor template's
`storage-adapter-import-placeholder` markers show the intended production
path is the S3 storage adapter (e.g. `@payloadcms/storage-s3` against
Cloudflare R2). Local disk is acceptable for the rollback leg; switch to
S3 before the leg hosts real media. Back up the database regardless —
uploads are the only other durable state.

## Re-pointing the mobile app

The app's `MAIN_URL` (`funiq/src/config/index.tsx`, private repo) must be
rebuilt to point at this app's origin before the app consumes the hosted
API. Fix the list-hook image-prefix bug in the same rebuild (parity
checklist §2.3 Q1). App builds happen in the private repo only.

## Re-sync cadence

No content rebuild loop exists — Payload serves the database live, nothing
is baked at build time for content. Re-run the sync (workflow_dispatch)
only when the licensed source or the deploy recipe changes.

## Rollback

Redeploy the previous flat mirror commit — the database is external, so a
rollback never needs a data migration. The leg itself is the fallback for
the app/admin half; storefront A/B routing is documented in
`nvoos-astro-velocity-setup.md`.

## Smoke (CI parity gate)

The workflow boots the assembled app against a throwaway Postgres and
asserts the licensed app's contract (`/admin`, `/api/products` Payload
envelope, globals, categories/brands/colors/statuses/promocodes, assets,
`/`). The same harness runs locally —
`examples/funiq-bridge-velocity/README.md` → "Local smoke".
