# Archive Directory

This directory contains historical documentation that has been organized for reference purposes. The documentation was reorganized in November 2025 to improve navigation and discoverability.

## Directory Structure

### `/compliance/`
WordPress Coding Standards (WPCS) and PHPCS compliance documentation.

**Contains:**
- PHPCS compliance reports
- WPCS status reports
- Compliance verification summaries
- PHPCS documentation and quick references
- Violation flowcharts and fix plans

### `/implementations/`
Implementation summaries and technical details for features developed over time.

**Contains:**
- Feature implementation summaries
- Technical implementation guides
- MCP protocol implementation details
- Migration guides

### `/phases/`
Development phase documents tracking the evolution of the plugin.

**Contains:**
- Phase completion summaries
- Development phase status documents
- Phase planning documents
- "What's next" roadmaps

### `/fixes/`
Bug fix summaries and issue resolutions.

**Contains:**
- Bug fix summaries
- Issue resolution documents
- Performance fix reports
- Security fix summaries
- Federation and mesh fixes
- Checkbox implementation fixes
- Regulatory and API fixes
- Visual guides for fixes

### `/features/`
Feature documentation and specifications.

**Contains:**
- Feature summaries
- Feature model preferences
- Feature specifications

### `/code-reviews/`
Historical code review reports and assessments.

**Contains:**
- Code review reports from various dates
- Code quality assessments
- Review summaries
- Code review and documentation updates

### `/testing/`
Test infrastructure and testing documentation.

**Contains:**
- Bug reports (archived)
- Test setup guides
- Testing checklists
- JavaScript test infrastructure setup

### Root Archive Files
Various historical summaries, visual guides, and status documents.

**Contains:**
- Task completion summaries
- Visual guides and diagrams
- Enhancement roadmaps
- Delivery summaries
- Security checks and implementation summaries
- Token management documentation
- Optimization recommendations
- Pull request summaries
- Submission summaries

## Purpose

These archived documents are preserved for:
- **Historical reference** - Understanding how features evolved
- **Development context** - Background on why decisions were made
- **Troubleshooting** - Learning from past issues and solutions
- **Documentation completeness** - Ensuring no information is lost

## Usage

When referencing archived documentation:
1. Check if more current documentation exists in the main docs/ directory
2. Use archived docs to understand historical context or evolution of features
3. Refer to current documentation for latest practices and guidelines
