# Veo Video Generation Debug Guide

## Issue
Videos are being generated by Google Veo and the cron polling is working (`wp_mcp_ai_poll_veo_video` is active), but videos are not appearing in the WordPress Media Library when requested from chat client using OpenAI provider.

## How the System Works

### Normal Flow
1. User requests video generation through chat client (using OpenAI provider)
2. OpenAI calls the `generate_veo_video` tool
3. Tool submits video generation request to Google Veo API
4. Tool returns async job info: `{async: true, job_id: 'veo_xxx', status: 'pending'}`
5. WordPress schedules cron job `wp_mcp_ai_poll_veo_video` to poll for completion
6. Cron executes every 5 seconds to check if video is ready
7. When ready, cron downloads video from Google
8. Cron saves video to WordPress Media Library
9. Cron stores result with attachment_id
10. OpenAI can call `check_video_status` tool to get the result
11. User sees the video attachment ID and URL

### Key Components
- **Tool**: `includes/tools/class-wp-mcp-ai-tool-generate-veo-video.php`
- **Service**: `includes/services/class-wp-mcp-ai-gemini-video-generation-service.php`
- **Cron Hook**: `wp_mcp_ai_poll_veo_video`
- **Status Checker**: `includes/tools/class-wp-mcp-ai-tool-check-video-status.php`

## Enhanced Logging (Added)

The following log events have been added to help debug the issue:

### 1. Video Processing Started
**Event**: `veo_async_processing_video`
**Message**: "Processing completed video from Google"
**Data**: `job_id`, `model`

### 2. Video Download Started
**Event**: `veo_downloading_video`
**Message**: "Downloading generated video from Google"
**Data**: `uri_host`, `uri_path`

### 3. Video Download Success
**Event**: `veo_video_downloaded`
**Message**: "Successfully downloaded video from Google"
**Data**: `size_bytes`

### 4. Video Download Failed
**Event**: `Veo video download failed` (error log)
**Data**: `error`, `code`

### 5. Video Save Started
**Event**: `veo_async_saving_to_media`
**Message**: "Attempting to save video to WordPress media library"
**Data**: `job_id`, `user_id`, `has_video_data`, `video_size`

### 6. Video Save Success
**Event**: `veo_video_saved_successfully`
**Message**: "Veo video successfully saved to WordPress media library"
**Data**: `job_id`, `attachment_id`, `url`

**Event**: `veo_video_saved`
**Message**: "Veo generated video saved to Media Library"
**Data**: `attachment_id`, `duration`, `file_path`, `user_id`

### 7. Video Save Failed
**Event**: `Veo video save to media library failed` (error log)
**Data**: `job_id`, `error`, `code`

### 8. Completion
**Event**: `veo_async_completed`
**Message**: "Veo async video generation completed successfully" or "...completed with errors"
**Data**: `job_id`, `status`, `attempts`

## How to Debug

### Step 1: Enable WordPress Debug Logging
Add to `wp-config.php`:
```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
define( 'WP_MCP_AI_DEBUG', true );
```

### Step 2: Enable Plugin Logging
Go to **WordPress Admin → Settings → WP oOS → Enable Logging**

### Step 3: Generate a Test Video
1. Use chat client to request video generation
2. Note the `job_id` returned (e.g., `veo_6922c60e7a5df8.13278386`)

### Step 4: Check Cron Status
Go to **WordPress Admin → Tools → Scheduled Events** (if you have WP Crontrol plugin)
or check via WP-CLI:
```bash
wp cron event list --format=table
```

Look for `wp_mcp_ai_poll_veo_video` with your job_id

### Step 5: Check Logs
View logs in one of these ways:

**Option A: WordPress Debug Log**
```bash
tail -f wp-content/debug.log | grep -i veo
```

**Option B: Plugin Logs (via WP-CLI)**
```bash
wp option get wp_mcp_ai_recent_errors --format=json | jq
wp option get wp_mcp_ai_recent_activity --format=json | jq
```

**Option C: WordPress Admin**
Go to **Settings → WP oOS** and check the log viewer

### Step 6: Check for Specific Events
Look for these events in order:
1. `veo_async_queued` - Job was queued
2. `veo_async_processing_video` - Cron started processing
3. `veo_downloading_video` - Download started
4. `veo_video_downloaded` - Download succeeded
5. `veo_async_saving_to_media` - Save started
6. `veo_video_saved_successfully` - Save succeeded
7. `veo_video_saved` - Final save confirmation
8. `veo_async_completed` - Job completed

### Step 7: Check Media Library
If all logs show success, check the Media Library:

**Option A: WordPress Admin**
1. Go to **Media → Library**
2. Switch to "List" view
3. Look for "Veo Generated Video"
4. Check the attachment ID matches the log

**Option B: WP-CLI**
```bash
wp post list --post_type=attachment --post_mime_type=video/mp4 --format=table
```

**Option C: Direct Database Query**
```sql
SELECT ID, post_title, post_author, post_date, guid 
FROM wp_posts 
WHERE post_type = 'attachment' 
AND post_mime_type = 'video/mp4' 
ORDER BY ID DESC 
LIMIT 10;
```

### Step 8: Check Job Result
Use the `check_video_status` tool or WP-CLI:
```bash
wp option get wp_mcp_ai_cron_result_{job_id}
```

## Common Issues and Solutions

### Issue 1: Video Download Fails
**Symptoms**: Log shows `Veo video download failed`
**Causes**:
- Google API key is invalid or expired
- Network timeout (video downloads can take up to 5 minutes)
- Google Cloud Storage URL requires authentication

**Solutions**:
- Verify Gemini API key in Settings → WP oOS → Providers
- Check network connectivity
- Review error message for specific issue

### Issue 2: Video Save Fails
**Symptoms**: Log shows `Veo video save to media library failed`
**Causes**:
- WordPress upload directory permissions
- Disk space full
- File size exceeds limits

**Solutions**:
```bash
# Check upload directory permissions
ls -la wp-content/uploads/
# Should be writable by web server user

# Check disk space
df -h

# Check PHP upload limits
php -i | grep upload_max_filesize
php -i | grep post_max_size
```

### Issue 3: Video Saved But Not Visible
**Symptoms**: Logs show success but video not in Media Library
**Causes**:
- User filter applied in Media Library
- Post author is 0 (no author)
- Video metadata not generated

**Solutions**:
1. In Media Library, click "All media items" to remove filters
2. Switch between "Grid" and "List" view
3. Search by attachment ID
4. Check database directly:
```sql
SELECT * FROM wp_posts WHERE ID = {attachment_id};
```

### Issue 4: Cron Not Executing
**Symptoms**: Video stays in "pending" status
**Causes**:
- WordPress cron disabled
- Server cron not configured
- Cron scheduling failed

**Solutions**:
- Check if WP-Cron is disabled in wp-config.php
- Manually trigger cron:
```bash
wp cron event run --due-now
```
- Force execute specific job:
```bash
wp cron event run wp_mcp_ai_poll_veo_video {job_id}
```

### Issue 5: AI Provider Not Checking Status
**Symptoms**: Video is saved but user doesn't see it in chat
**Causes**:
- OpenAI not calling `check_video_status` tool
- Tool response not formatted correctly

**Solutions**:
- Verify OpenAI has access to `check_video_status` tool
- Check tool is registered in tool registry
- Manually check status via WP-CLI:
```bash
wp eval "
\$service = new WP_MCP_AI_Gemini_Video_Generation_Service();
print_r(\$service->get_async_status('{job_id}'));
"
```

## Expected Behavior

When everything works correctly:

1. **Logs show**:
   - Video download succeeded (with file size)
   - Video save succeeded (with attachment ID)
   - Job completed successfully

2. **Media Library shows**:
   - New video attachment
   - Title: "Veo Generated Video: {prompt}"
   - Type: video/mp4
   - Author: Requesting user

3. **Chat client shows**:
   - Completion message with attachment ID
   - Video URL
   - Option to view/download

   - Job ID

## Technical Details

### Video File Handling
- **Format**: MP4 (H.264 video, AAC audio)
- **Max Size**: Varies by Veo model (typically 5-50 MB for 5-8 second videos)
- **Storage**: `wp-content/uploads/` directory
- **Filename**: `veo-video-{uniqid}.mp4`
- **Download Timeout**: 300 seconds (5 minutes)

### Cron Polling
- **Hook**: `wp_mcp_ai_poll_veo_video`
- **Interval**: 5 seconds
- **Max Attempts**: 60 (5 minutes total)
- **Timeout Detection**: 10 seconds before PHP timeout
- **Fallback**: Auto-switches to async if timeout approaching

### User Context
- **User ID**: Preserved from original request
- **Capabilities**: Requires `upload_files`
- **Multisite**: Checks site membership
- **Author**: Video attachment author = requesting user

## Summary

The Veo video generation system is designed to:
1. Accept async video generation requests
2. Poll Google Veo API for completion
3. Download generated video from Google Cloud Storage
4. Save video to WordPress Media Library
5. Notify user when complete

The enhanced logging added will help identify exactly where the process fails if videos aren't appearing in the Media Library.
