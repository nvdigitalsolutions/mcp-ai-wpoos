### Checkout hardening series (sub-projects `addons/checkout-api/` + `plugins/nvoos-content-graph/`)

- **#6611** — checkout-api: the "Create product & price in Stripe" admin action was idempotent on the stored `product_id`/`price_id`, so after switching Stripe accounts the old account's IDs still matched and both creations were skipped (button appeared dead). New `retrieve_product()`/`retrieve_price()` client methods (error data carries `http_status` + `stripe_code`); `ensure_product_and_price()` verifies stored IDs against the current key first: valid → no-op, 404 `resource_missing` → stale IDs cleared + recreated (`recreated` notice), price on the wrong product → recreated, other failures → abort (`verify` notice). 9 new tests (3 stripe-client + 6 admin-page); 37/37 on WP 6.9.
- **#6612** — content-graph: purchase-modal price block now renders "Introductory price — prices are subject to change." (`price_subject_change` i18n key → `nvoos-cg-price-change`), deliberately avoiding fake limited-time claims per the hard rules in `docs/checkout-enhancement-plan.md` §6.
- **#6613** — checkout-api: Stripe rejects the full `statement_descriptor` for card charges created with `automatic_payment_methods`, so **every live `/session` call failed with a 424**. `/session` now sends `statement_descriptor_suffix` (2–22 chars, ≥1 letter, appended to the account's prefix; invalid values drop out), the settings key stays `statement_descriptor` so the stored value remains valid. 42/42 (216 assertions) on WP 6.9 + 7.1.
