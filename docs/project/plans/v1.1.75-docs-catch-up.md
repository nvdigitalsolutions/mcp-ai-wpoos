| PR | Production files | Change |

| #6482 | `addons/pro/includes/services/class-wp-mcp-ai-result-delivery-service.php`, `addons/pro/includes/tools/chat-channels/class-wp-mcp-ai-pro-tool-unified-channel-broadcast.php`, `addons/pro/includes/class-wp-mcp-ai-pro-schedule-manager.php`, `addons/pro/assets/js/schedule-manager.js` | **Telegram broadcast credentials fix** — assistant-run schedules with Telegram broadcast fataled (`TypeError: … credentials must be of type array, string given`): the edit modal stored inline credentials as a raw JSON string and the Result Delivery Service passed it through to `unified_channel_broadcast`'s array-typed parameter. | #6486 | `includes/tools/class-wp-mcp-ai-tool-wake-up-context.php`, `includes/admin/class-wp-mcp-ai-admin-orchestration-dashboard.php` (+ sub-project: `plugins/nvoos-content-graph/**` Memory Bridge, `plugins/nvoos-content-graph-ai-platform/**` dashboard port, `addons/checkout-api/**` vendor retarget) | **Content Graph memory bridge + NV oOS Complete checkout** — the base `wake_up_context` tool gains a `wp_mcp_ai_wake_up_context_graph_retriever` filter seam: the standalone Content Graph plugin registers it and serves graph retrieval (agent/wing/room anchors + keyword blend); `graph`/`auto` mode now activates when the filter has listeners (not only when the bundled Graphify class exists — byte-identical when no listener). The bridge also projects `wp_mcp_ai_memory_stored` + `nvoos_content_graph/memory_stored` memories into the standalone graph with advisory degradation (bridge failures never break memory writes). The orchestration dashboard detects any connected graph bridge and resolves the "Open Graph Explorer" link accordingly. The Content Graph checkout now sells the **NV oOS Complete bundle** (base + Pro) with a conflict guard (409 when another NV oOS copy exists) — nvoos-content-graph bumps **1.0.4 → 1.0.6**. |
| #6488 | `addons/pro/includes/services/class-wp-mcp-ai-result-delivery-service.php`, `addons/pro/includes/tools/class-wp-mcp-ai-pro-tool-create-pro-schedule.php`, `-update-pro-schedule.php`, `addons/pro/includes/rest/class-wp-mcp-ai-pro-schedule-rest-controller.php`, `addons/pro/includes/admin/sections/class-wp-mcp-ai-section-schedule-manager.php`, `addons/pro/assets/js/schedule-manager.js` | **Scheduled Telegram delivery credential fallback** — cron delivery to Telegram failed (`No valid credentials found for the telegram channel.`) because credential resolution had only three tiers (connection_id, inline credentials, unimplemented filter). New **tier-4 fallback**: first *enabled* Remote Sites connection of the channel type (preferring one the schedule's assistant is assigned to); destination fields merge from the schedule config. UI: Result Delivery rows show a Remote Sites connection dropdown (name + ID + enabled state; never credentials). |
