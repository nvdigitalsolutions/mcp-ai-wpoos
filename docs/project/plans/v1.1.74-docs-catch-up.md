### Production-touching PRs (everything else in the window is test-only, CI-only, build-only, or sub-project)

| PR | Production files | Change |
|---|---|---|
| #6460 | `includes/google/class-wp-mcp-ai-google-calendar-client.php`, `-google-calendar-scopes.php` (+ platform mirror) | **Google Calendar date-query + free/busy fix** — `WP_MCP_AI_Google_Calendar_Client::request()` built query strings with `add_query_arg()`, which leaves values unencoded, so the literal `+` in normalized RFC3339 offsets was decoded by Google as a space and every `time_min`/`time_max` query returned HTTP 400 (unfiltered listings worked because they carry no `+`). Every query value is now `rawurlencode()`d before `add_query_arg()` (offsets, IANA timezone names, free-text searches). Also: `calendar.freebusy` added to the Standard scope profile so `check_google_calendar_availability` works after a normal connection — applies to **new** OAuth grants; existing connections keep their stored scopes until reconnected. Platform mirror updated identically. |
| #6465 | `addons/pro/includes/services/class-wp-mcp-ai-markdown-converter.php` (new), `-result-delivery-service.php`, `addons/pro/includes/class-wp-mcp-ai-pro-schedule-manager.php`, `addons/pro/assets/js/schedule-manager.js` | **Result Delivery email presentation formats** — new dependency-free `WP_MCP_AI_Markdown_Converter` (headings, emphasis, inline/fenced code, lists, blockquotes, protocol-allowlisted links, HRs, GFM tables; every text node HTML-escaped and the fragment passes a `wp_kses` allowlist, so raw assistant HTML can never reach the email body; inline-only email-safe styling). `format_email()` produces an `html_body` alongside the Markdown `text/plain` part; new `format` setting (`both` \| `html` \| `markdown`, default `both` — existing schedules get formatted HTML with zero migration); `send_email()` routes bodies per format (Nodemailer multipart/alternative; `wp_mail` single content-type). Schedule sanitizer allowlists `format`; edit modal gains a format dropdown. New `tests/test-pro-result-delivery-email-format.php` (14 tests). |
| #6469 | `addons/pro/includes/class-wp-mcp-ai-pro-schedule-manager.php`, `addons/pro/includes/tools/class-wp-mcp-ai-pro-tool-update-pro-schedule.php`, `addons/pro/assets/js/schedule-manager.js` | **Schedule Manager assistant-prompt editing** — `assistant_run` schedules could not show or edit their prompt: the edit modal only rendered `workflow` fields and `update_schedule()` ignored `assistant_config`.
