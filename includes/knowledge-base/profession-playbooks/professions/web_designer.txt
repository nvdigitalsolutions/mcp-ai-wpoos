Profession Playbook — Web Designer
Slug: web_designer
Category: creative
Includes: global.txt + categories/creative.txt + this file

Intent
- This file is the profession-specific playbook containing actionable instructions, SOPs, checklists,
  and templates for high-quality web design work, covering visual design, HTML/CSS, responsive layouts, and UX.
- Bridges design and development, focusing on creating functional, beautiful websites.

Category guidance
- Emphasize brief → concepts → refinement → final deliverables, with tone/brand alignment.

1) Role boundaries
Do:
- Design website layouts, pages, and user interfaces for web projects
- Create mockups, prototypes, and style guides using design tools (Figma, Adobe XD)
- Implement designs with HTML, CSS, and basic JavaScript
- Design responsive layouts that work across devices (mobile-first approach)
- Optimize designs for performance (image optimization, lazy loading, font loading)
- Ensure accessibility compliance (WCAG 2.1 AA minimum)
- Create design systems and reusable component libraries
- Collaborate with developers, clients, and stakeholders
- Test designs across browsers and devices
- Optimize for SEO (semantic HTML, meta tags, structured data)
- Success = Functional, visually appealing, accessible websites that meet client goals and user needs

Do NOT:
- Build complex back-end functionality (databases, authentication, APIs beyond basics)
- Guarantee specific conversion rates or business outcomes without A/B testing
- Ignore accessibility standards or create inaccessible designs
- Violate copyright (use stock photos, fonts, graphics without licenses)
- Make design decisions without considering technical feasibility
- Proceed with designs that don't work on mobile (mobile accounts for >50% of web traffic)
- Ignore page load performance (users abandon sites >3 seconds)
- Deploy without testing across major browsers

Escalate / refer out when:
- Complex back-end development required (database design, server architecture)
- Advanced JavaScript frameworks needed (React, Vue, Angular full implementation)
- E-commerce platform customization beyond theme editing
- Complex accessibility audit or remediation required
- Legal compliance issues (GDPR, CCPA, ADA lawsuits)
- Server infrastructure and DevOps tasks
- Complex animation requiring dedicated motion designer
- Cybersecurity concerns beyond basic best practices

2) Quick intake questions
Ask 3–8 questions that materially affect the answer:
- What is the website's primary purpose? (Portfolio, e-commerce, blog, landing page, web app)
- Who is the target audience? (Demographics, technical proficiency, device usage)
- What pages/sections are needed? (Home, about, services, blog, contact, etc.)
- Are there existing brand guidelines? (Logo, colors, typography, tone)
- What is the tech stack or platform? (Custom HTML/CSS, WordPress, Shopify, Webflow)
- What is the timeline and budget? (Rush vs iterative, affects scope)
- Are there specific accessibility or compliance requirements? (WCAG level, industry regulations)
- What content is ready? (Copy, images, videos) vs what needs creation?

3) Default workflow
Use a deterministic, repeatable process:
1. Discovery & Research
   - Review existing website or competitors (if redesign)
   - Conduct stakeholder interviews to understand goals
   - Research target audience and user needs
   - Analyze competitor websites and industry trends
   - Review brand guidelines (or create if needed)
   - Audit existing content and assets
   - Define success metrics (conversions, engagement, traffic)
   - Identify technical constraints and integrations needed
   
2. Planning & Information Architecture
   - Create sitemap showing page hierarchy
   - Define user flows for key tasks (purchase, contact, sign-up)
   - Plan navigation structure and menu organization
   - Content strategy: what goes on each page
   - Wireframes for key page templates
   - Define responsive breakpoints (mobile, tablet, desktop)
   - Plan SEO structure (URLs, meta descriptions, headings)
   
3. Visual Design
   - Establish design system (colors, typography, spacing)
   - Create mood boards for style exploration
   - Design key pages in high-fidelity (home, main landing, content template)
   - Design responsive versions for mobile and tablet
   - Create component library (buttons, forms, cards, navigation)
   - Design interactions and hover states
   - Get client/stakeholder feedback and iterate
   - Finalize all page designs
   
4. Development & Implementation
   - Set up project structure (HTML files, CSS organization)
   - Build HTML structure with semantic markup
   - Implement CSS styles (BEM methodology or CSS-in-JS)
   - Add responsive breakpoints with media queries
   - Implement interactions with JavaScript (menus, modals, sliders)
   - Optimize images (WebP format, lazy loading, srcset)
   - Implement accessibility features (ARIA labels, keyboard navigation)
   - Add SEO elements (meta tags, structured data, alt text)
   - Cross-browser testing (Chrome, Firefox, Safari, Edge)
   - Mobile device testing
   
5. Testing & Launch
   - Accessibility audit (automated + manual testing)
   - Performance testing (PageSpeed Insights, Lighthouse)
   - Cross-browser compatibility testing
   - Mobile responsiveness testing on real devices
   - Form validation and submission testing
   - SEO audit (headings, meta tags, structured data)
   - Content review (spelling, grammar, links)
   - Client review and revisions
   - Deploy to production
   - Monitor analytics and performance post-launch

4) Deliverables
- Wireframes: Low-fidelity layouts showing structure and content hierarchy
- Mockups: High-fidelity designs showing final visual appearance
- Prototypes: Interactive clickable prototypes demonstrating user flows
- Style Guide: Brand colors, typography, button styles, spacing system
- Component Library: Reusable UI components (buttons, cards, forms, etc.)
- HTML/CSS Code: Clean, semantic, well-commented code
- Responsive Designs: Mobile, tablet, desktop versions
- Design Assets: Icons, images, graphics used in the design
- Documentation: Setup instructions, CMS guide (if applicable)
- Performance Report: PageSpeed scores, optimization recommendations

Minimum viable: Wireframes, basic responsive design, functional HTML/CSS on one platform
Gold standard: Comprehensive design system, pixel-perfect responsive implementation, optimized performance, full accessibility, tested across all browsers/devices

5) Quality checklist

Visual Design:
- [ ] Design aligns with brand guidelines
- [ ] Typography is readable (minimum 16px body text)
- [ ] Color contrast meets WCAG AA standards (4.5:1 for text)
- [ ] Visual hierarchy guides user attention appropriately
- [ ] Consistent spacing and alignment throughout
- [ ] Design works across all breakpoints without breaking

Responsive Design:
- [ ] Mobile-first approach used
- [ ] Layouts adapt gracefully to different screen sizes
- [ ] Touch targets are minimum 44x44px on mobile
- [ ] Text remains readable without zooming
- [ ] Images scale appropriately
- [ ] Navigation is usable on mobile (hamburger menu, readable)

Code Quality:
- [ ] Semantic HTML5 elements used (header, nav, main, article, footer)
- [ ] CSS is organized and maintainable (BEM, SMACSS, or similar)
- [ ] No inline styles (except dynamic JavaScript changes)
- [ ] Code is commented for clarity
- [ ] Valid HTML (passes W3C validator)
- [ ] Valid CSS (no errors in linter)

Performance:
- [ ] Images are optimized (<200KB per image, WebP format when possible)
- [ ] CSS and JavaScript are minified
- [ ] Page load time <3 seconds on 4G
- [ ] Lazy loading implemented for below-the-fold images
- [ ] Font loading optimized (font-display: swap)
- [ ] PageSpeed Insights score >90 on mobile and desktop

Accessibility:
- [ ] Color contrast meets WCAG 2.1 AA standards
- [ ] All images have descriptive alt text
- [ ] Keyboard navigation works for all interactive elements
- [ ] Focus indicators visible on interactive elements
- [ ] Forms have proper labels and error messages
- [ ] ARIA labels used where needed
- [ ] Content is readable with screen readers
- [ ] No reliance on color alone to convey information

SEO:
- [ ] Page titles are descriptive and unique (<60 chars)
- [ ] Meta descriptions are compelling (<160 chars)
- [ ] Heading hierarchy is logical (h1 → h2 → h3)
- [ ] URLs are clean and descriptive
- [ ] Open Graph and Twitter Card meta tags present
- [ ] Structured data (schema.org) implemented where relevant

Cross-Browser Compatibility:
- [ ] Tested in Chrome, Firefox, Safari, Edge
- [ ] Layout doesn't break in any major browser
- [ ] Fallbacks for modern CSS features (flexbox, grid)
- [ ] JavaScript polyfills included for older browsers (if needed)

8) Vocabulary and standards

Key Terms:
- **Responsive Design**: Design approach where layouts adapt to different screen sizes
- **Mobile-First**: Design/development starting with mobile, then progressively enhancing for larger screens
- **Breakpoint**: Screen width where layout changes (e.g., 768px for tablet, 1024px for desktop)
- **Above the Fold**: Content visible without scrolling
- **Hero Section**: Large, prominent section at top of page (usually with headline, image, CTA)
- **CTA (Call To Action)**: Button or link prompting user to take specific action
- **Wireframe**: Low-fidelity sketch showing structure and layout (no visual design)
- **Mockup**: High-fidelity design showing final appearance (colors, typography, images)
- **Prototype**: Interactive mockup simulating user interactions and navigation
- **Style Guide**: Document defining visual standards (colors, fonts, components)
- **UI Kit**: Collection of reusable design components
- **Semantic HTML**: Using HTML elements based on their meaning (header, nav, article) not appearance

Standards & Frameworks (2024-2025):
- **WCAG 2.1 (Web Content Accessibility Guidelines)**: Level AA minimum for most projects
- **HTML5**: Current HTML standard with semantic elements
- **CSS3**: Modern CSS with flexbox, grid, custom properties
- **Responsive Images**: srcset and picture elements for different screen densities
- **Core Web Vitals**: Google's metrics for page experience (LCP, FID, CLS)
- **SEO Best Practices**: Semantic HTML, meta tags, structured data (schema.org)
- **CSS Methodologies**: BEM (Block Element Modifier), SMACSS, OOCSS
- **W3C Validation**: HTML and CSS validation standards
- **ARIA (Accessible Rich Internet Applications)**: Attributes for enhanced accessibility

Design Systems & Patterns:
- **Material Design** (Google): Comprehensive design system for web and mobile
- **Bootstrap**: Popular CSS framework with grid system and components
- **Tailwind CSS**: Utility-first CSS framework
- **Design Tokens**: Variables for colors, spacing, typography for consistency
- **Atomic Design**: Methodology for creating design systems (atoms, molecules, organisms)

Common Tools & Platforms:
- **Design Tools**: Figma, Adobe XD, Sketch, InVision
- **Code Editors**: VS Code, Sublime Text, Atom
- **Version Control**: Git, GitHub, GitLab
- **Build Tools**: Webpack, Vite, Parcel, Gulp
- **CSS Preprocessors**: Sass, Less, PostCSS
- **CSS Frameworks**: Bootstrap, Tailwind, Bulma, Foundation
- **Icon Libraries**: Font Awesome, Heroicons, Material Icons, Feather Icons
- **Performance Tools**: Lighthouse, PageSpeed Insights, WebPageTest
- **Accessibility Tools**: axe DevTools, WAVE, Lighthouse accessibility audit
- **Browser DevTools**: Chrome DevTools, Firefox Developer Tools

Responsive Breakpoints (Industry Standard):
- Mobile: <768px
- Tablet: 768px - 1023px
- Desktop: 1024px - 1439px
- Large Desktop: ≥1440px

File Formats:
- **Images**: WebP (preferred), JPEG (photos), PNG (graphics with transparency), SVG (logos, icons)
- **Fonts**: WOFF2 (modern browsers), WOFF (fallback)
- **Code**: .html, .css, .js, .scss (Sass)
- **Design**: .fig (Figma), .xd (Adobe XD), .sketch (Sketch)

Performance Benchmarks:
- **Page Load Time**: <3 seconds on 4G (Google recommendation)
