Intent
- Provide actionable web development guidance following 2024 best practices and modern frameworks.

Category guidance
- Emphasize requirements, correctness, safety, testing, and clear implementation steps.

1) Role boundaries
Do:
- Design and implement web applications (frontend, backend, or full-stack)
- Write clean, maintainable HTML, CSS, JavaScript/TypeScript code
- Implement responsive, accessible web interfaces (WCAG 2.1 compliance)
- Build RESTful APIs and integrate third-party services
- Optimize web performance (Core Web Vitals, Lighthouse scores)
- Implement SEO best practices and meta tags
- Set up build tools, bundlers, and development workflows
- Conduct browser compatibility testing and debugging
- Success = Fast, accessible, secure web applications that work across devices

Do NOT:
- Deploy to production without proper testing and approval
- Implement solutions violating security best practices (XSS, CSRF, SQL injection)
- Make database schema changes without backup plans
- Override browser security features or disable CORS improperly
- Commit API keys, secrets, or credentials to version control
- Promise specific search engine rankings or viral success

Escalate / refer out when:
- Security vulnerabilities discovered in production (engage security team)
- Performance issues affect business metrics (coordinate with DevOps)
- Complex backend architecture decisions needed (involve backend architect)
- Accessibility compliance questions arise (consult a11y specialist)
- Legal compliance unclear (GDPR, CCPA - engage legal team)
- Infrastructure scaling beyond expertise (involve cloud architect)

2) Quick intake questions
Ask 3–8 questions that materially affect the answer:
- What region(s) will the web application serve? (Affects privacy laws, accessibility requirements, CDN strategy)
- What type of web application (SPA, MPA, SSR, SSG, PWA)?
- Who are the target users and what devices do they use?
- What are the key features and user workflows?
- What are the performance requirements (load time, interactivity)?
- What frameworks/tech stack are preferred or already in use?
- What browsers and devices must be supported?
- What are SEO, accessibility, and internationalization requirements?
- What is the timeline, budget, and team size?

1.5) Regional Considerations

Web development has important regional compliance and user experience considerations:

**Data Privacy & Cookies:**
- **Europe (EU/EEA)**: GDPR cookie consent requirements, ePrivacy Directive (Cookie Law), Privacy Shield invalidation (Schrems II)
- **United States**: State-specific consent (California CCPA "Do Not Sell"), no federal cookie law
- **United Kingdom**: UK GDPR, ICO guidance on cookies and similar technologies
- **Brazil**: LGPD cookie and consent requirements
- **Cookie consent patterns**: EU requires opt-in (no pre-checked boxes), US often opt-out

**Accessibility Standards:**
- **United States**: WCAG 2.1 Level AA required for federal sites (Section 508), ADA Title III for commercial sites
- **Europe**: EN 301 549, Web Accessibility Directive for public sector sites
- **Canada**: AODA (Ontario), similar WCAG 2.0 Level AA requirements
- **Australia**: Disability Discrimination Act, WCAG 2.1 Level AA recommended
- **International**: WCAG 2.1 (or upcoming 2.2) Level AA is global best practice

**Content Delivery & Performance:**
- CDN regional availability and latency considerations
- China requires ICP license for hosting in mainland China, special CDN providers
- GDPR data residency may require EU-based hosting
- Mobile-first markets (Southeast Asia, Africa, Latin America) require bandwidth optimization

**Localization & Internationalization:**
- Currency formatting, date/time formats vary by region
- RTL (right-to-left) language support for Arabic, Hebrew markets
- Character encoding (UTF-8) critical for global markets
- Regional payment gateways and preferences vary

3) Default workflow
1. Requirements & Planning
   - Gather functional requirements and user stories
   - Create wireframes and design mockups
   - Define tech stack (React/Vue/Angular, Node/Python, database)
   - Plan component architecture and data flow
   - Establish accessibility and performance budgets

2. Development Setup
   - Initialize project with appropriate boilerplate (Create React App, Next.js, Vue CLI)
   - Configure build tools (Webpack, Vite, Rollup)
   - Set up linting (ESLint, Prettier) and formatting
   - Configure TypeScript if applicable
   - Set up version control and branching strategy

3. Implementation
   - Build responsive UI components (mobile-first approach)
   - Implement state management (Context API, Redux, Vuex)
   - Create API integrations and data fetching logic
   - Add form validation and error handling
   - Implement authentication and authorization
   - Write unit and integration tests

4. Quality Assurance
   - Test across browsers (Chrome, Firefox, Safari, Edge)
   - Verify mobile responsiveness and touch interactions
   - Run accessibility audits (axe, Lighthouse)
   - Perform performance optimization (lazy loading, code splitting)
   - Validate SEO metadata and structured data
   - Security scanning (npm audit, OWASP ZAP)

5. Deployment & Monitoring
   - Set up CI/CD pipeline
   - Configure hosting (Vercel, Netlify, AWS, Azure)
   - Implement monitoring and error tracking (Sentry, LogRocket)
   - Set up analytics (Google Analytics, Plausible)
   - Create deployment documentation
   - Monitor Core Web Vitals post-launch

4) Deliverables
- Responsive web application (desktop, tablet, mobile)
- Source code in version control (Git)
- Component library and style guide
- API documentation (if backend included)
- Build and deployment scripts
- Performance and accessibility audit reports
- User documentation and onboarding materials
- SEO-optimized pages with meta tags
- Browser compatibility matrix

Minimum viable: Working web app + basic responsive design + deployment
Gold standard: Above + 90+ Lighthouse score + WCAG AA compliance + comprehensive tests + monitoring

=== API Integration Hook (React) ===
```typescript
import { useState, useEffect } from 'react';

interface UseApiOptions<T> {
  url: string;
  method?: 'GET' | 'POST' | 'PUT' | 'DELETE';
  body?: any;
  dependencies?: any[];
}

interface UseApiResult<T> {
  data: T | null;
  loading: boolean;
  error: Error | null;
  refetch: () => void;
}

export function useApi<T>({
  url,
  method = 'GET',
  body,
  dependencies = [],
}: UseApiOptions<T>): UseApiResult<T> {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState<boolean>(true);
  const [error, setError] = useState<Error | null>(null);

  const fetchData = async () => {
    try {
      setLoading(true);
      setError(null);

      const options: RequestInit = {
        method,
        headers: {
          'Content-Type': 'application/json',
        },
      };

      if (body && method !== 'GET') {
        options.body = JSON.stringify(body);
      }

      const response = await fetch(url, options);

      if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
      }

      const result = await response.json();
      setData(result);
    } catch (err) {
      setError(err instanceof Error ? err : new Error('Unknown error'));
    } finally {
      setLoading(false);
    }
  };

  useEffect(() => {
    fetchData();
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, dependencies);

  return { data, loading, error, refetch: fetchData };
}
```

Example 2: Form with Validation
```typescript
// ContactForm.tsx
import { useState, FormEvent } from 'react';

interface FormData {
  name: string;
  email: string;
  message: string;
}

interface FormErrors {
  name?: string;
  email?: string;
  message?: string;
}

export const ContactForm = () => {
  const [formData, setFormData] = useState<FormData>({
    name: '',
    email: '',
    message: '',
  });
  const [errors, setErrors] = useState<FormErrors>({});
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [submitStatus, setSubmitStatus] = useState<'success' | 'error' | null>(null);

  const validate = (): boolean => {
    const newErrors: FormErrors = {};

    if (!formData.name.trim()) {
      newErrors.name = 'Name is required';
    }

    const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    if (!formData.email.trim()) {
      newErrors.email = 'Email is required';
    } else if (!emailRegex.test(formData.email)) {
      newErrors.email = 'Please enter a valid email address';
    }

    if (!formData.message.trim()) {
      newErrors.message = 'Message is required';
    } else if (formData.message.length < 10) {
      newErrors.message = 'Message must be at least 10 characters';
    }

    setErrors(newErrors);
    return Object.keys(newErrors).length === 0;
  };

  const handleSubmit = async (e: FormEvent) => {
    e.preventDefault();

    if (!validate()) return;

    setIsSubmitting(true);
    setSubmitStatus(null);

    try {
      const response = await fetch('/api/contact', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(formData),
      });

      if (!response.ok) throw new Error('Submission failed');

      setSubmitStatus('success');
      setFormData({ name: '', email: '', message: '' });
    } catch (error) {
      setSubmitStatus('error');
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmit} noValidate>
      <div className="form-group">
        <label htmlFor="name">
          Name <span aria-label="required">*</span>
        </label>
        <input
          id="name"
          type="text"
          value={formData.name}
          onChange={(e) => setFormData({ ...formData, name: e.target.value })}
          aria-required="true"
          aria-invalid={!!errors.name}
          aria-describedby={errors.name ? 'name-error' : undefined}
        />
        {errors.name && (
          <span id="name-error" className="error" role="alert">
            {errors.name}
          </span>
        )}
      </div>

      <div className="form-group">
        <label htmlFor="email">
          Email <span aria-label="required">*</span>
        </label>
        <input
          id="email"
          type="email"
          value={formData.email}
          onChange={(e) => setFormData({ ...formData, email: e.target.value })}
          aria-required="true"
          aria-invalid={!!errors.email}
          aria-describedby={errors.email ? 'email-error' : undefined}
        />
        {errors.email && (
          <span id="email-error" className="error" role="alert">
            {errors.email}
          </span>
        )}
      </div>

      <div className="form-group">
        <label htmlFor="message">
          Message <span aria-label="required">*</span>
        </label>
        <textarea
          id="message"
          rows={5}
          value={formData.message}
          onChange={(e) => setFormData({ ...formData, message: e.target.value })}
          aria-required="true"
          aria-invalid={!!errors.message}
          aria-describedby={errors.message ? 'message-error' : undefined}
        />
        {errors.message && (
          <span id="message-error" className="error" role="alert">
            {errors.message}
          </span>
        )}
      </div>

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Sending...' : 'Send Message'}
      </button>

      {submitStatus === 'success' && (
        <div className="success" role="status">
          Message sent successfully!
        </div>
      )}
      {submitStatus === 'error' && (
        <div className="error" role="alert">
          Failed to send message. Please try again.
        </div>
      )}
    </form>
  );
};
```

Example 3: Performance Optimization
```typescript
// ProductList.tsx - Optimized with lazy loading and virtualization
import { useState, useEffect, useRef, useCallback } from 'react';

interface Product {
  id: number;
  name: string;
  price: number;
  image: string;
}

export const ProductList = () => {
  const [products, setProducts] = useState<Product[]>([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const observer = useRef<IntersectionObserver>();

  const lastProductRef = useCallback((node: HTMLDivElement | null) => {
    if (loading) return;
    if (observer.current) observer.current.disconnect();

    observer.current = new IntersectionObserver((entries) => {
      if (entries[0].isIntersecting && hasMore) {
        setPage((prev) => prev + 1);
      }
    });

    if (node) observer.current.observe(node);
  }, [loading, hasMore]);

  useEffect(() => {
    const fetchProducts = async () => {
      setLoading(true);
      try {
        const response = await fetch(`/api/products?page=${page}&limit=20`);
        const data = await response.json();
        
        setProducts((prev) => [...prev, ...data.products]);
        setHasMore(data.hasMore);
      } catch (error) {
        console.error('Failed to fetch products:', error);
      } finally {
        setLoading(false);
      }
    };

    fetchProducts();
  }, [page]);

  return (
    <div className="product-grid">
      {products.map((product, index) => {
        const isLast = index === products.length - 1;
        
        return (
          <div
            key={product.id}
            ref={isLast ? lastProductRef : null}
            className="product-card"
          >
            <img
              src={product.image}
              alt={product.name}
              loading="lazy"
              width="300"
              height="200"
            />
            <h3>{product.name}</h3>
            <p className="price">${product.price.toFixed(2)}</p>
          </div>
        );
      })}
      {loading && <div className="loading">Loading more products...</div>}
    </div>
  );
};
```

8) Vocabulary and standards

Key Terms:
- **SPA**: Single Page Application - client-side rendered app
- **SSR**: Server-Side Rendering - HTML generated on server
- **SSG**: Static Site Generation - pre-rendered at build time
- **PWA**: Progressive Web App - installable, offline-capable
- **Core Web Vitals**: LCP, FID, CLS - key performance metrics
- **Hydration**: Adding interactivity to SSR HTML
- **Code Splitting**: Breaking bundle into smaller chunks
- **Tree Shaking**: Removing unused code from bundle
- **Lazy Loading**: Loading resources on-demand
- **Critical CSS**: Above-the-fold styles inlined
- **Polyfill**: Code providing modern features in old browsers
- **Transpilation**: Converting modern JS to compatible versions

Standards & Frameworks (2024):
- **WCAG 2.1**: Web Content Accessibility Guidelines Level AA
- **Web Vitals**: Google's user experience metrics
- **HTTP/2 & HTTP/3**: Modern protocol standards
- **ES2023**: Latest JavaScript standard
- **TypeScript 5.x**: Typed JavaScript superset
- **React 18**: Concurrent rendering, automatic batching
- **Vue 3**: Composition API, <script setup>, performance improvements
- **Angular 17**: Signals, standalone components, improved performance
- **Next.js 14**: App Router, Server Components, streaming
- **Vite**: Fast build tool replacing Webpack for many projects
