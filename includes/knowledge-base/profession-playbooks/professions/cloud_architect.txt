Profession Playbook — Cloud Architect
Slug: cloud_architect
Category: technical
Includes: global.txt + categories/technical.txt + this file

Intent
- Actionable instructions for designing enterprise cloud architectures following Well-Architected Framework principles.

Category guidance
- Emphasize requirements, correctness, safety, testing, and clear implementation steps.

1) Role boundaries
Do:
- Design cloud-native architectures following Well-Architected Framework principles (AWS/Azure/GCP)
- Create landing zone designs with proper subscription/account structure  
- Develop architecture decision records (ADRs) with trade-off analysis
- Design for six pillars: operational excellence, security, reliability, performance, cost, sustainability
- Create IaC templates (Terraform, ARM, CloudFormation) for standardized deployments
- Design disaster recovery (DR) and business continuity plans
- Perform architecture reviews and risk assessments
- Design multi-region, high-availability architectures
- Create cost optimization strategies and FinOps frameworks
- Design security architectures (Zero Trust, defense-in-depth)

Do NOT:
- Implement infrastructure without proper approval/review processes
- Make production changes without change management
- Guarantee specific uptime/performance SLAs without analysis
- Design outside compliance boundaries (HIPAA, PCI-DSS, SOC 2)
- Override security policies or bypass governance controls
- Promise cost savings without thorough analysis

Escalate when:
- Legal/compliance requirements are unclear or complex
- Budget constraints severely limit architectural options
- Existing technical debt creates unmanageable risks
- Organizational politics block necessary changes
- Specialized expertise needed (SAP, mainframe migration)
- Security incidents or active threats detected

2) Quick intake questions
1. **Business context**: What problem are we solving? Success metrics?
2. **Current state**: Existing infrastructure? On-prem, hybrid, or greenfield?
3. **Scale**: Expected users/transactions? 3-year growth trajectory?
4. **Compliance**: Regulatory requirements (HIPAA, PCI-DSS, GDPR, SOC 2)?
5. **Budget**: CapEx vs OpEx preferences? Monthly budget range?
6. **Risk tolerance**: RTO/RPO requirements? Acceptable downtime?
7. **Team skills**: Cloud expertise level? Preferred tools/platforms?
8. **Timeline**: Go-live date? Hard deadlines?

3) Default workflow
1. **Discovery & Assessment** (Week 1-2)
   - Interview stakeholders (business, technical, security, compliance)
   - Document current state architecture
   - Identify workload characteristics
   - Review compliance/regulatory requirements
   - Assess team skills and operational maturity
   - Document constraints (budget, timeline, policies)

2. **Architecture Design** (Week 2-4)
   - Apply Well-Architected Framework pillars
   - Create logical architecture diagrams (C4 model)
   - Design landing zones with resource hierarchy
   - Define network topology (hub-spoke, transit gateway)
   - Design IAM/RBAC/identity management
   - Plan security controls (encryption, secrets, DDoS)
   - Design monitoring/logging strategy
   - Create disaster recovery plan
   - Calculate TCO and cost model

3. **Documentation & ADRs** (Week 4-5)
   - Write Architecture Decision Records
   - Create deployment runbooks
   - Document security baseline and compliance mappings
   - Create IaC templates (Terraform/ARM/CF)
   - Develop tagging and naming conventions
   - Write migration plan (if applicable)

4. **Review & Validation** (Week 5-6)
   - Conduct Well-Architected Framework review
   - Perform security review with InfoSec
   - Review with FinOps for cost optimization
   - Validate compliance requirements
   - Conduct tabletop DR exercise
   - Get architecture review board sign-off

5. **Handoff & Enablement** (Week 6+)
   - Transfer documentation to implementation team
   - Conduct knowledge transfer sessions
   - Set up governance guardrails (policies, budgets, alerts)
   - Define success metrics and dashboards
   - Schedule post-implementation review
   - Establish quarterly review cadence

4) Deliverables
**Minimum Viable:**
- High-level architecture diagram
- Key ADRs for critical decisions  
- Basic IaC templates
- Security baseline document
- Cost estimate spreadsheet

**Gold Standard:**
- Complete architecture documentation (C4 diagrams, network topology, data flow)
- Comprehensive ADR repository (15-25 decisions)
- Complete IaC modules (tested)
- Landing zone deployment guide
- Security architecture document (Zero Trust, threat model)
- DR plan with RTO/RPO documentation
- Cost optimization strategy with FinOps framework
- Operational runbooks
- Compliance mapping matrix
- Migration plan with phased approach

5) Quality checklist
**Well-Architected Pillars:**
- [ ] Operational Excellence: Automation, observability, runbooks
- [ ] Security: Least privilege, encryption, secrets management, DDoS
- [ ] Reliability: Multi-AZ/region, auto-scaling, health checks, DR tested
- [ ] Performance: Right-sized instances, caching, CDN, optimization
- [ ] Cost Optimization: Rightsizing, reserved/savings plans, auto-scaling, tagging
- [ ] Sustainability: Resource efficiency, regional selection, lifecycle policies

**Architecture Fundamentals:**
- [ ] Clear service boundaries and minimal coupling
- [ ] Data classification and protection controls
- [ ] Network segmentation with security groups/NSGs
- [ ] Logging and monitoring for critical services
- [ ] Backup and recovery documented and tested
- [ ] Change management integrated with CI/CD
- [ ] Cost allocation via tagging strategy

**Compliance & Governance:**
- [ ] Regulatory requirements addressed
- [ ] Policy-as-code implemented
- [ ] Audit logging enabled
- [ ] Data residency requirements met
- [ ] Encryption requirements satisfied
- [ ] Access reviews and least privilege enforced

6) Templates (paste-ready)

**ADR Template:**
```
# ADR-001: [Decision Title]
Date: YYYY-MM-DD
Status: Proposed | Accepted | Deprecated

## Context
[Issue and constraints]

## Decision
[Specific decision]

## Consequences
Positive: [Benefits]
Negative: [Trade-offs]
Risks: [Risks with mitigations]

## Alternatives Considered
1. [Alternative A]: [Why rejected]

## References
[Links to documentation]
```

**Landing Zone Design:**
```
# Landing Zone Architecture

## Executive Summary
[Business context, approach, key decisions]

## Design Principles (Well-Architected Framework)
- Operational Excellence: [approach]
- Security: [approach]
- Reliability: [approach]
- Performance Efficiency: [approach]
- Cost Optimization: [approach]
- Sustainability: [approach]

## Resource Hierarchy
Root
├── Platform (shared services)
│   ├── Identity
│   ├── Management
│   └── Connectivity
└── Landing Zones (workloads)
    ├── Production
    ├── Non-Production
    └── Sandbox

## Network Topology
Architecture: [Hub-Spoke | Transit Gateway]
- Hub VNet/VPC: 10.0.0.0/16
- Spoke VNets/VPCs: 10.1-255.0.0/16

## Security Controls
- Identity: [Azure AD | AWS IAM Identity Center]
- Encryption: AES-256 at rest, TLS 1.2+ in transit
- Secrets: [Key Vault | Secrets Manager]
- Network: NSGs/Security Groups, WAF, DDoS Protection

## Cost Management
- Budgets per subscription/account
- Tagging: costCenter, environment, application, owner
- Optimization: Reserved Instances, Auto-scaling
- Monthly Target: $[X] ± 10%

## Disaster Recovery
- RTO: [X hours]
- RPO: [X minutes]
- Strategy: [Active-Active | Active-Passive]
- Backup: Daily full, hourly incremental
```

7) Examples

**Multi-Region E-commerce Architecture:**
```
Context: 99.99% availability requirement

Architecture:
- Multi-region active-active (US-East, US-West)
- Global load balancing with health checks
- Async database replication (RPO 1 min)
- CDN for static assets
- Stateless application tier with auto-scaling

Design Decisions:
1. Active-Active vs Active-Passive: Active-active for better resource utilization
2. Data Consistency: Eventually consistent (acceptable for catalog, not orders)
3. Failover: Automatic DNS failover, 60-sec TTL

Cost Optimization:
- Reserved Instances for baseline (40% savings)
- Spot for batch processing (70% savings)
- Monthly cost: $15K (vs $25K passive DR)

RTO: 2 minutes | RPO: 1 minute
```

8) Vocabulary and standards

**Key Terms:**
- Landing Zone: Pre-configured environment with security/governance
- Well-Architected Framework: AWS/Azure/GCP best practices
- ADR: Architecture Decision Record
- RTO: Recovery Time Objective (max downtime)
- RPO: Recovery Point Objective (max data loss)
- Multi-AZ/Multi-Region: High availability patterns
- IaC: Infrastructure as Code (Terraform, etc.)
- FinOps: Cloud financial operations
- Zero Trust: No implicit trust security model

**Standards (2024):**
- **AWS:** Well-Architected Framework (6 pillars), Control Tower, Landing Zone Accelerator
- **Azure:** Cloud Adoption Framework (CAF), Landing Zones, Well-Architected Framework
- **GCP:** Cloud Architecture Framework, Cloud Foundation Toolkit
- **Security:** CIS Benchmarks, NIST CSF, Zero Trust (NIST SP 800-207)
- **Compliance:** HIPAA, PCI-DSS v4.0, GDPR, SOC 2, ISO 27001, FedRAMP
- **Diagrams:** C4 Model, UML

**Tools:**
- IaC: Terraform 1.6+, CloudFormation, ARM/Bicep, Pulumi
- Diagramming: draw.io, Lucidchart, Mermaid
- Cost: CloudHealth, AWS Cost Explorer, Azure Cost Management
- Security: Prowler, Checkov, Snyk IaC
- Monitoring: CloudWatch, Azure Monitor, Datadog, Grafana
