# Data

## Purpose

Ships bundled, read-only reference data — auto-generated compliance controls (ISO 27001 / SOC 2 / HIPAA) and the canonical AI model catalog — so the plugin can run without touching `docs/` or external services.

## Tier

| | |
|---|---|
| **Distribution** | Base (compliance data feeds the Pro Dashboard but is generated and shipped from Base) |
| **PHP target** | 7.4+ |
| **Loaded by** | `includes/bootstrap/loader.php` (`class-wp-mcp-ai-compliance-data.php`) and `includes/class-wp-mcp-ai-model-rate-limits-cct.php` / `includes/class-wp-mcp-ai-model-catalog-migration.php` (read `model-catalog.json`) |
| **Optional dependencies** | none — bundled data is the canonical source of truth at runtime |

## Public Surface

| Symbol | File | Used by |
|---|---|---|
| `WP_MCP_AI_Compliance_Data::get_iso27001_controls()` | `class-wp-mcp-ai-compliance-data.php` | `WP_MCP_AI_Pro_Dashboard`, `WP_MCP_AI_Pro_Dashboard_REST` |
| `WP_MCP_AI_Compliance_Data::get_soc2_*()` / `get_hipaa_*()` | `class-wp-mcp-ai-compliance-data.php` | Pro Dashboard percentage widgets |
| `model-catalog.json` (data file) | `model-catalog.json` | `WP_MCP_AI_Model_Rate_Limits_CCT`, `WP_MCP_AI_Model_Catalog_Migration`, `WP_MCP_AI_Model_Discovery_Service`, `discover_new_models` tool |

> **Do Not Edit** — `class-wp-mcp-ai-compliance-data.php` is auto-generated by `bin/generate-compliance-data.php`. Hand edits will be overwritten on the next regeneration. Edit the source markdown in `docs/compliance/{iso27001,soc2,hipaa}/Statement-of-Applicability.md` instead, then run the generator and commit both the markdown and the regenerated PHP. The same rule applies to `model-catalog.json`: edit the catalog fixture and re-run `WP_MCP_AI_Model_Catalog_Migration` rather than patching consumers around stale data.

## Inputs / Outputs / Neighbors

- **Reads from:** nothing at runtime — data is embedded in PHP and JSON; no I/O. The build script reads `docs/compliance/*/Statement-of-Applicability.md` at generate time.
- **Writes to:** nothing. Read-only data tier.
- **Upstream callers:** the Pro Dashboard (`includes/admin/class-wp-mcp-ai-pro-dashboard.php`, `…-rest.php`), the model rate-limits CCT, the model-discovery service, the `discover_new_models` tool.
- **Downstream collaborators:** none — this folder sits at the leaves of the dependency graph.
- **Events fired:** none.
- **Events listened to:** none. The catalog is exposed for runtime override via the `wp_mcp_ai_model_catalog` and `wp_mcp_ai_model_catalog_source_path` filters, which are declared and applied by the consumers (not by this folder).

## Conventions

- **Auto-generated file — do not hand-edit.** Run `php bin/generate-compliance-data.php` from the plugin root after any change to `docs/compliance/**`. The script parses the three Statements of Applicability and rewrites `class-wp-mcp-ai-compliance-data.php` in place.
- A `wp-content/uploads/mcp-ai/model-catalog.json` override is honoured at runtime; that path is for admins, not for committing changes. Update the bundled catalog here if a fix should ship with the plugin.
- Keep this folder data-only — no business logic, no hooks, no side effects. If logic is needed, add it to `includes/services/` and let it read from here.
- Both files must round-trip safely: the compliance class is regenerated whole, and `model-catalog.json` is validated by `tests/test-model-catalog.php`. Don't introduce partial-update patterns.

## Tests

```bash
vendor/bin/phpunit tests/test-model-catalog.php
```

`test-model-catalog.php` validates the JSON shape and required fields. Compliance data is exercised indirectly through `tests/test-pro-dashboard-*.php` (e.g. `test-pro-dashboard-monitoring.php`, `test-pro-dashboard-charts.php`).
