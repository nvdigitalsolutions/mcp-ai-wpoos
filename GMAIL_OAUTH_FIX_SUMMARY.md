# Gmail OAuth Fix - Summary for User

## What Was the Problem?

You were getting this error when trying to connect Gmail:
```
Access blocked: This app's request is invalid
Error 400: redirect_uri_mismatch
```

This error means that the redirect URI your WordPress site is sending to Google doesn't match what's configured in your Google Cloud Console OAuth 2.0 credentials.

## What Changed?

I've made your life easier by adding a new field in the admin UI that shows you the EXACT redirect URI you need to configure in Google Cloud Console.

### Before (The Hard Way)
- You had to manually construct the redirect URI
- Easy to make typos or mistakes
- HTTP vs HTTPS confusion
- Didn't know if you got it right until you tried

### After (The Easy Way)
- The exact redirect URI is displayed in a field
- Just click to select and copy it
- No more guessing or manual construction
- Direct link to Google Cloud Console included

## What You Need to Do

### Quick Fix (5 minutes)

1. **Go to WordPress Admin → NV oOS Dashboard → Remote Sites**

2. **Edit your Gmail connection** (or create a new one)

3. **Set Connection Type to "Gmail (Email Service)"**

4. **Look for the "Authorized Redirect URI" field** - it will show something like:
   ```
   https://bots.nvdigital.solutions/wp-admin/admin.php?page=wp-mcp-ai-remote-sites&oauth_handler=gmail_oauth_callback
   ```

5. **Click on the URL to select it, then copy it** (Ctrl+C / Cmd+C)

6. **Click the "Open Google Cloud Console" link** (or go to https://console.cloud.google.com/apis/credentials)

7. **Edit your OAuth 2.0 Client ID**

8. **Find "Authorized redirect URIs" section**

9. **Click "+ ADD URI"**

10. **Paste the URL you copied** (make sure it matches EXACTLY)

11. **Click SAVE**

12. **Wait 30-60 seconds** for Google's systems to update

13. **Back in WordPress, enter your Client ID and Client Secret**

14. **Click "Update Connection"**

15. **Click "Connect to Gmail"** - should work now! ✅

## Troubleshooting

### Still getting the error?

1. **Double-check the redirect URI matches exactly** (copy from the admin UI field)
2. **Make sure you saved in Google Cloud Console** (click the SAVE button at the bottom)
3. **Wait a full minute** after saving in Google Cloud Console
4. **Try in incognito/private browsing** to rule out cache issues
5. **Verify you're editing the correct OAuth client** in Google Cloud Console
6. **Check you're in the correct Google Cloud Project** (dropdown at the top of Google Cloud Console)

### Different error now?

If you see a different error, check:
- Gmail API is enabled in Google Cloud Console
- Your site uses HTTPS (required for OAuth)
- Client ID and Secret are correct
- You're using the latest version of the plugin

## Technical Details (For Developers)

The issue was that users had to manually construct the redirect URI, which led to errors. The fix adds a read-only field that displays the exact URI generated by this code:

```php
$gmail_redirect_uri = admin_url( 'admin.php?page=wp-mcp-ai-remote-sites&oauth_handler=gmail_oauth_callback' );
```

This URI is shown in the admin UI when editing Gmail or Google Drive connections, making it foolproof to copy the correct value into Google Cloud Console.

The OAuth flow uses `oauth_handler` parameter instead of `action` because Google restricts the `action` parameter name in redirect URIs (as documented in the previous fix).
