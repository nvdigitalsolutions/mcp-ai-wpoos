# File Header Examples

> Proposal 166 (Unix Theory P8–P12). Copy the shape that matches the file's
> class. Replace the licence with the one from the nearest manifest; when in
> doubt, run `php bin/check-file-docs.php --explain=<path>`.
>
> Rules: licence first, purpose second, code third. Never restate the filename
> or the type signature. 1–5 lines for a module; 1–3 for a test or config.

## What fails review

| Smell | Why |
|---|---|
| `@fileoverview Helpers.` | restates the filename, answers none of the three questions |
| A paragraph repeating the type signature | the type system already says it |
| A tutorial in a test header | tests get one line: what they pin + fixtures |
| A header on a generated bundle | excluded by path, not by prose |
| `@package` in TS/Rust | ambiguous; ownership lives in the folder README |
| `@since` in TS/Rust | drifts from package semver; use release tags |
