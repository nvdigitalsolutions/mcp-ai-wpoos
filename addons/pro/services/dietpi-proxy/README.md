# DietPi SSH Proxy Service

> Node.js companion service for the NV oOS DietPi Pro Toolkit.
> Provides SSH command execution when the WordPress host lacks the
> PHP `ssh2` extension and `proc_open` is disabled.

## When to Use

This proxy is a **Phase 3 fallback** — it is only needed when:

1. The PHP `ssh2` extension is not installed, **and**
2. `proc_open` is disabled (common in shared hosting)

If either `ssh2` or `proc_open` is available, the DietPi toolkit works
directly without this service.

## Quick Start

```bash
cd addons/pro/services/dietpi-proxy

# Install dependencies
npm install

# Configure (via environment variables)
export SSH_HOST=192.168.1.100
export SSH_USER=root
export SSH_KEY="$(cat ~/.ssh/id_ed25519)"

# Start the proxy
npm start
```

## Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `SSH_HOST` | Yes | — | DietPi device hostname or IP |
| `SSH_PORT` | No | `22` | SSH port |
| `SSH_USER` | No | `root` | SSH username |
| `SSH_KEY` | No* | — | Path to private key file or inline PEM content |
| `SSH_PASSPHRASE` | No | — | Key passphrase (if encrypted) |
| `SSH_PASSWORD` | No* | — | Password (fallback if no key) |
| `PORT` | No | `3099` | HTTP listen port |
| `PROXY_TOKEN` | No | auto-generated | Shared secret for X-Proxy-Token auth |

\* Either `SSH_KEY` or `SSH_PASSWORD` must be set.

## WordPress Integration

In the DietPi toolkit settings, set the proxy URL:

```
Proxy URL: http://localhost:3099
Proxy Token: <auto-generated token>
```

The toolkit's SSH client will automatically fall back to the proxy
when neither `ssh2` nor `proc_open` is usable.

## API Endpoints

### `GET /health`
Check if the proxy is running.

### `POST /exec`
Execute a shell command on the DietPi device.

**Headers:** `X-Proxy-Token: <token>`
**Body:** `{ "command": "echo hello", "timeout": 30 }`
**Response:** `{ "stdout": "hello", "stderr": "", "exit_code": 0, "duration_ms": 123 }`

## Security

- The proxy listens on `localhost` by default (bind it to `127.0.0.1` only).
- All requests require the `X-Proxy-Token` header with a shared secret.
- SSH credentials are never exposed in responses.
- Consider running behind a reverse proxy with TLS if exposing beyond localhost.

## Running as a Service (systemd)

```ini
# /etc/systemd/system/dietpi-proxy.service
[Unit]
Description=DietPi SSH Proxy for NV oOS
After=network.target

[Service]
Type=simple
User=nobody
WorkingDirectory=/path/to/dietpi-proxy
Environment=SSH_HOST=192.168.1.100
Environment=SSH_USER=root
Environment=SSH_KEY=/home/nobody/.ssh/id_ed25519
Environment=PROXY_TOKEN=your-secure-token-here
ExecStart=/usr/bin/node src/index.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dietpi-proxy
```
