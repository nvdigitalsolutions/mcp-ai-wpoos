┌─────────────────────────────────────────────────────────────────────────────┐
│                              Data Flow                                      │
└─────────────────────────────────────────────────────────────────────────────┘

1. Error Occurs
   └─→ Component calls: do_action('wp_mcp_ai_error', $component, $message, $context)
       └─→ Error Tracking Service::track_error()
           └─→ Stores in WordPress Options
               └─→ Invalidates cache

2. Performance Report Generated
   └─→ Performance Reporter::generate_report()
       └─→ Calls Error Tracking Service::get_error_rate() for each component
           └─→ Service calculates rate (cached for 5 minutes)
               └─→ Reporter analyzes health status
                   └─→ Generates alerts if error rate > thresholds
                       └─→ Stores results in Performance Monitor CCT

3. Admin Views Dashboard
   └─→ Performance Reporter::get_performance_alerts()
       └─→ Returns sorted alerts (Critical → High → Medium)
           └─→ Admin sees real-time error rate status

┌─────────────────────────────────────────────────────────────────────────────┐
│                         Performance Metrics                                 │
└─────────────────────────────────────────────────────────────────────────────┘

Caching Strategy:
  └─→ Error rates cached for 5 minutes (Transients)
  └─→ Performance baselines cached in WordPress Options
  └─→ CCT queries use JetEngine's query optimization

Resource Usage:
  └─→ Memory: Minimal (singleton pattern, cached rates)
  └─→ Database: One option row for all errors
  └─→ CPU: Minimal (sanitization, JSON encoding)
  └─→ Storage: ~50-100KB for 1000 errors

Retention Policy:
  └─→ Errors: 7 days automatic cleanup
  └─→ Performance data: Configurable via filters
  └─→ Max errors: 1000 (configurable constant)

┌─────────────────────────────────────────────────────────────────────────────┐
│                            Alert Thresholds                                 │
└─────────────────────────────────────────────────────────────────────────────┘

Error Rate Levels:
  ├─→ CRITICAL (>10%)  : Immediate action required
  │                      Health status: 'critical'
  │                      Recommendation: Review logs immediately
  │
  ├─→ HIGH (>5%)       : Investigation needed
  │                      Health status: 'warning'
  │                      Recommendation: Investigate error sources
  │
  └─→ MEDIUM (>1%)     : Monitoring recommended
                         Health status: 'fair' (if otherwise good)
                         Recommendation: Monitor error patterns

Performance Degradation:
  └─→ Response time comparison (first third vs last third)
      ├─→ >20% slower: 'degrading' trend
      ├─→ >20% faster: 'improving' trend
      └─→ Otherwise:   'stable' trend
